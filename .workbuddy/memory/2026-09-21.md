### 本次修掉的关键问题
1. **`Environment.upper_machine` 是 OneToOneField**：seed 按名字 `get_or_create` 会撞
   `UNIQUE constraint failed: environments_environment.upper_machine_id`。
   改为「先按上位机认领已有环境 → 再按名字查 → 最后新建」，并允许改名。
2. **`scan_environment_logs()` 返回结构**：`subsystems` 是**字符串列表**，
   `global_catalog` 才是 `{"name": ..., "fms": [...]}` 字典列表。
3. **模拟机 awk 语义错误（重要）**：旧实现只按 `print $N` 粗匹配，后端真实程序
   `{ ... if (ts > e) exit; print $0 }` 里的 `print $0` 被当成"取第 0 字段"，
   导致归档日志全部 0 行。已重写为解析 `-v` 赋值 + 按程序特征分派
   （首末行探测 / 时间窗口过滤 / 字段提取 / 整行透传）。
4. **实时日志在 ASGI 下永远 0 字节（后端真实缺陷）**：
   Django `StreamingHttpResponse.__aiter__` 对**同步**迭代器会走
   `sync_to_async(list)(streaming_content)`，即先把整条流物化成列表。
   对永不结束的实时 SSE 流等于永远不输出。
   修复：`apps/logsources/views.py` 的 `EnvironmentLogViewSet.live` 改为**异步生成器**，
   用一条专用线程推进阻塞的同步生成器，经 `asyncio.Queue` 交给事件循环；
   与项目既有 `DeploymentEventBus.event_stream()`（本身就是异步生成器）风格一致。

### 可选 STT（已装好并运行）
- `scripts/stt_up.sh` 会建 `backend/.venv-stt` 并装 `requirements-stt.txt`
  （fastapi + faster-whisper + ctranslate2 + onnxruntime），监听 `127.0.0.1:8001`。
- 模型 `small`（CPU / int8），`--no-preload`：首次识别才加载模型。
- `/health` 返回 `{"ok":true,"model":"small","model_loaded":false,"device":"cpu","compute_type":"int8"}`。
- **坑**：`stt_up.sh` 的健康检查原来用 `curl -sS` 且丢弃输出，HTTP 502（例如沙箱网络代理
  在端口无监听时返回的 `upstream connect failed`）也算 curl 成功 → 会误报"健康检查通过"。
  已改为 `curl -fsS`。
- **坑**：以「后台任务 + 继承 stdout/stderr 管道」方式启动 `start_stt.py` 时进程不监听 8001；
  把输出重定向到文件（`>> scripts/run/stt.out 2>&1`）后 2 秒内正常就绪。脚本里的
  `nohup ... > "$RUN_DIR/stt.out" 2>&1 &` 本身就带重定向，是正确姿势。
