## 两个 bash 坑（都踩了）
- **全角字符紧跟变量名**：`"未找到 uv（$UV）。"` → bash 把 `（` 的字节并进变量名，报
  `PY<mangled>: unbound variable`。所有「变量紧跟中文/全角标点」处必须写 `${VAR}`。
- **`printf '%-12s'` 不按显示宽度补空格**：CJK 占 2 列却算 3 字节，中英混排表格会歪。
  `sim.sh` 里用 `pad()` 自己算：`显示列数 = 字节数 - 宽字节数/3`。

## 日志正文改造：关键字模板 + 流程阶段框
- 用户诉求两条：①日志要体现「不同流程阶段」；②`>()` 之后要有**固定关键字模板**
  （「xxx流程开始 / xxx获取数据」），出口是 `<()` 之后同一个关键字 + `end`。
- `loggen.PHASE_KEYWORDS`（函数名→中文短语）承载关键字；`loggen.log_message()` 自动拼成
  `[函数] >() enter 批次扫片 开始 <正文>` / `[函数] <() leave 批次扫片 end <正文>`。
  **新增调用链函数必须同步登记**，否则静默退回英文函数名。
- `loggen.expand_stage_groups(rows)` 给「每条流上连续的同阶段」套 `[Stage_<码>]` 框，
  框自己也吃关键字模板，入口/出口带 `step=n/N`；收尾状态在 `loggen._STAGE_STATUS`
  （EXPOSURE=aborted、INTERLOCK_TRIP=tripped…），别让阶段框把故障掩盖成 ok。
- 剧本改造：`_DEBUG_GROUPS`（6 组 → 35 行 / 5 阶段）、`livesim._ROUND_ROWS`
  （→ 76 行 / 12 阶段，`SCRIPT_LENGTH` 从 50 变 76，一轮 ≈38s）。
- ⚠️ **踩到的最阴的坑：展开器出口字段错位**。普通行内部是
  `(位置, 流, 阶段, 级别, 函数, 相位, 正文)`，而阶段框的头/尾行当时按
  `(..., 函数, 相位, 级别, ...)` 另建元组 —— 同一个返回值里两种行字段含义不同，
  调用方按一种解包另一种必然串位。症状极其隐蔽：行还是那一行，只是
  `[Stage_EXPOSURE]` 跑进「级别」槽、函数名变成 `enter`、rpc 变成 `fm:enter:NNN`，
  **只查行数/阶段码数量完全查不出来**。修法：内部行统一一种布局，出口只做一次切片。
- 诊断时还自己踩了第二个坑：项目标记是 `>()` / `<()`（**括号紧贴、无空格**），
  写诊断正则时写成 `[<>] \(\)`（要求中间有空格）→ 得出「一行都没匹配上」的假结论。
  先用 `loggen.ENTRY_MARKER` 打印出来对一遍再写正则。

## 环境地址改为真实网络 IP
- `fleet.detect_machine_host()`：枚举 `ifconfig` + `_address_rank()` 内网优先。
  **别用「UDP 连 8.8.8.8」探地址** —— 挂 VPN 会探到 utun 的 `28.0.0.1`，
  非内网且会被后端 `_is_private_host` 拒。实测得到 `192.168.1.10`。
- 上位机/下位机**同一个 IP，靠 2222/2223 端口区分**；按地址定位用
  `fleet.machine_by_endpoint(host, port)`（单键 `host` 会同时命中上下位机）。
- 多地址绑定：`sshd.MachineServer(bind_hosts=…)` 每地址一个 accept 线程；
  `atlog_site.serve(hosts=…)` 返回 `ReportSiteGroup`。默认 `fleet.bind_hosts()`
  = `(MACHINE_HOST, 127.0.0.1)`。
- ⚠️ **「端口在监听」≠「网络 IP 能连上」**。改造前起的旧进程只绑回环，
  `lsof -iTCP:2222` 照样有输出；`sim.sh status` 若只打印配置里的地址就显示一切正常，
  真正报错要等后端去连：`Unable to connect to port 2222 on 192.168.1.10`。
  新增 `env.sh:port_open_on`（对具体地址做 TCP 连接）/ `listen_addrs`（列出实际绑定地址），
  `start` 的跳过判据带上地址（只绑回环 ⇒ 判陈旧、自动重启），status 显示**实际绑定地址**。
  也别用 `lsof -i@host` 过滤：多个 `-i` 是「或」，会把同端口其它地址上的无关进程也列出来。
- 改了 host 要连带处理两处**按主机名命名的目录/记录**：
  * executor 树 `elog/<lower.host>/<子系统>/`（`loggen.executor_family`）—— 旧名字目录不会被
    覆盖，而 `prune_tree` 是 40 文件/轮的小批量，靠 init 重跑要好几轮。内容一样时
    **一次 `os.replace(old_dir, new_dir)` 改名**即可。
  * `seed._drop_stale_sim_entities()`：只清机器会卡在 `ProtectedError` ——
    `Environment.upper_machine` 是 PROTECT，旧环境不退绑旧机器就永远删不掉，
    前端「环境资源」会出现**两条同名 SIM-EUV-01**、其中一条恒 error。
    **先删同名环境、再删旧机器**；`_ensure_environment` 的 `.first()` 要补 `order_by("id")`
    否则认领到哪一个是数据库说了算。
- 顺序：`init` → `seed` → 重启 `stream`/`backend` → `selftest`。
  跳过 `seed` 的症状是自检报「尚未 seed」+「未找到 executor 文件」。
- `sim.sh` 加 `machine_ip()`，横幅/状态/登录提示全部改用网络 IP，不再出现 `sim-upper.localhost`。
