## 两个新踩到的坑（都很值钱）
### 1. 长驻服务**不能**在后台工具调用里启动
- `sim.sh start stream` 放在 `run_in_background=true` 的调用里，**子进程在后台任务结束时被回收**：
  `scripts/run/stream.out` 只留下启动横幅、没有「已停止」，进程凭空消失、pidfile 残留。
  即使 `_spawn.py` 用了 `start_new_session=True` 也救不了。
- 结论：**起服务一律用前台调用**（fleet / site / stream / backend / frontend 都是）。
  后台调用只用来跑有始有终的任务（selftest、init、curl 探测）。
- 诊断口诀：pidfile 有值 ≠ 服务在跑。`ps -eo pid,etime,command | grep "simremote[.]cli stream"` 才是真相；
  `ps` 被沙箱拦时用 `pgrep -f`。

### 2. `init` 撞上「一轮最多删 50 个文件」的配额 → 半途失败并留下重复资产
- 现象：`sim.sh init` 报 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":50,"threshold":50,"scope":"turn"}`
  → `资产生成失败`。**删除配额是按「一个 assistant turn」计的**，
  同一轮里先跑过一次 `init`（清理 49 + 1）就已经把额度用光。
- 后果很隐蔽：`cpdgen` 按**当前锚点**给批次命名（本轮是 `..._022751 / _025251 / _031751 / _034251`），
  所以第二次 init 生成的是一套**新文件名**，旧的 `..._022715 / _025215 / _031715 / _034215` 删不掉就留着了
  → 每个模块目录 **8 个文件而不是 4 个**。症状是 `selftest` 的
  「后端按报告窗口筛出数据表格」命中两张表（期望 1 张）。
- 修法（**不用删除**，改名绕开配额）：`os.replace` 把旧批次搬进 `run/recycle/cpd_stale/<镜像路径>`，
  按 mtime 分组（新旧相差 ~35s，取 `newest - 5s` 为界最稳）。实测搬走 48 个，两个树都回到 4/模块。
- 顺序教训：**改日志内容 → 先停 `stream` → `init` → `seed` → 起 `stream`**。
  不停流的话，旧进程会在 `init` 重建之后继续往新文件里追加旧格式的行（这次残留了 10~12 行中文）。

## 自动化模拟部署 + 上下位机互信（两个 IP）—— 新功能
用户需求：「加入一个自动化模拟部署的过程，因为要上下位机互信，所以还需支持两个 IP 的
模拟，然后还能支持互信操作，然后支持每个步骤的部署日志打印输出」。

### 1. 两个 IP 怎么来的（关键约束）
- 本机只有 `127.0.0.1` 与 `192.168.1.10` 两个可绑定 IPv4（`28.0.0.1` 是 utun/VPN，
  `is_private` 为假，会被 ATLog 拒）。**`127.0.0.2` 默认绑不上**（`Errno 49`），
  需要 `sudo ifconfig lo0 alias 127.0.0.2 up`；受控环境里 `sudo` 直接 `operation not permitted`，
  所以只能**引导用户手动执行一次**（`scripts/sim.sh alias` 打印命令）。
- `fleet.resolve_machine_hosts()` 的分配策略（就是 `_host_pool()` 的先后顺序）：
  **lo0 别名（127.0.0.2/3）→ 网卡地址**；`_host_pool()` **刻意不含裸 127.0.0.1**
  （它作为"宣告地址"进库后跟网卡地址不是一个值，排查链路时会把"服务没起来"和
  "地址选错"混在一起）。没别名时两台共用网卡地址、靠端口 2222/2223 区分。
- 覆盖用 `SIM_UPPER_HOST` / `SIM_LOWER_HOST`（旧的 `SIM_MACHINE_HOST` 仍兼容，
  只当上位机地址、下位机自动避让）。
- ⚠️ 踩过：`_host_pool()` 一度把 `127.0.0.1` 硬编码进候选池，导致「下位机退化成回环」；
  而且中间一版 `spare` 过滤掉所有 `127.*`，会让**用户加了别名也用不上**
  （直接违背"支持两个 IP"）。正确写法是 `spare = [ip for ip in pool if ip not in taken]`，
  靠 `_host_pool()` 的排序决定优先级。

### 2. "互信"必须可验证，不能脚本自说自话
- `sshd.SimSSHServer.check_auth_publickey`：读该机台 `~/.ssh/authorized_keys`，
  按**公钥 blob（第 2 列）**比对；`get_allowed_auths` 返回 `publickey,password`。
  每次认证**重读文件**（不缓存）—— 刚铺完公钥就要能登录，缓存会掩盖真实故障。
- 每台机器**独立 host key**（`run/ssh_host_rsa_key_<key>`）：两台共用一把钥匙的话，
  `known_hosts` 里写谁都是同一串，"交换主机指纹"这步就成空动作了。
- `selftest` 因此能断言两条：**已授权私钥登录成功** + **未授权私钥被拒绝**（后者证明
  认证真的在校验，不是"谁来都放行"）。

### 3. `simremote/deploy.py`：7 步部署 + 分步日志
网络连通性 → 生成密钥对 → 交换主机指纹 → 双向分发公钥 → 校验正向免密 →
校验反向免密 → 写环境资源。`scripts/sim.sh deploy [--no-seed]`。
- **日志分两层**：控制台（中文进度 + 明细 + 耗时，失败即中断）；落盘（**全英文**）。
- 落盘位置：`/log/<user>/deploy/deploy_<ts>.log`（**每台机器一份**，本机视角）。
  ⚠️ **不能放 run 目录**：`file_index._run_log_identity` 会把任何"纯时间戳命名的 .log"
  当成 event 归档（`parse_archive_timestamp(stem)` 兜底分支），放进去会污染运行日志解析。
- 同时把每步作为**运行事件**追加进 `event.log`（严格合 RUN_PATTERN 十三字段，
  `[DEPLOY] ... [deploy] <step> ok (0.123s)`），于是前端「运行日志」也能看到这次部署。
  追加在**文件末尾**，不影响自检对开头 200 行的抽样。
- 部署日志里的 `record.notes` **不落盘**（那是中文明细），落盘只留
  `step n/N <english-name> ok|failed (秒)` —— 从结构上杜绝中文进日志。

- 地址现状：`_host_pool()` 只有 `192.168.1.10`（无 lo0 别名），所以两台机器**同地址靠端口区分**，
  `hosts_are_distinct() == False`。要变成两个独立 IP 需用户手动执行一次
  `sudo ifconfig lo0 alias 127.0.0.2 up && sudo ifconfig lo0 alias 127.0.0.3 up`
  再 `scripts/sim.sh restart fleet`（受控环境里 sudo 会 `operation not permitted`，只能用户自己敲）。
