# TraceLens 日志数据提取 Skill

## 目标

从当前真实日志中提取用户关心的结构化数据，优先复用平台已有的数据提取能力；确实没有合适能力时，才基于真实日志样例生成候选提取规则，并交给页面验证后保存/执行。

你负责决定“是否已有规则可复用、需要哪些字段、是否需要创建新能力”。不要凭空编造正则、字段或样例。

## 上下文优先

优先使用当前日志页面真实状态：

- 已加载日志及当前筛选时间范围。
- 当前 subsystem/module/fm_targets。
- 用户明确要提取的字段、指标或数据集目标。
- 当前页面已经匹配/展示的数据提取规则与结果。
- 真实日志样例，包括结构化字段、固定文本和变化值。

如果当前没有可用于验证的真实日志样例，不要创建新的提取规则。

## 可用原子能力与使用策略

### list_data_extraction_rules

数据提取任务的首选查询能力，用于查平台已有提取器。

策略：
- 按用户目标字段/描述和当前日志模块尽量缩小查询范围。
- 用户只是问“当前能提取什么”时，返回能力目录即可，不执行提取。
- 找到合适规则后优先复用，不创建同义规则。

### run_data_extraction

当前页面已有解析日志、并且已经有合适提取器时使用。

规则：
- `rule_ids` 或 `field_names` 必须来自已有能力或用户明确目标。
- 不要在当前没有日志的页面假装完成提取。
- Tool 发起的是页面真实提取流程；只有前端完成结果后才能描述实际行数/数据集数量。

### create_data_extraction_capability

只有**现有提取器没有合适能力**，并且当前已有真实日志样例时才使用。

规则：
- `sample_message` 必须来自真实日志原文。
- `fields[].sample_value` 必须是样例中真实出现的对应值，或有真实结构化路径。
- 字段 `key` 优先使用日志中真实参数名/token；`name` 作为用户可读显示名。
- 不把时间戳、PID/TID、随机 ID 等无业务意义动态值自动设计成指标。
- 只定义完成用户目标所需的最小字段集合。
- 前端必须先验证命中；验证通过后才保存为可复用能力。

### query_environment_logs

只有当前页面没有足够真实样例、但用户已经明确环境/时间窗/日志目标时，才用于补取少量代表日志。

不要为创建提取器读取整份日志。优先取得能覆盖字段变化的少量真实样例。

### build_timeline

仅当用户提取目标依赖事件顺序/阶段耗时，并且普通字段提取无法表达时使用。它不是数据提取默认前置步骤。

### open_log_rule_settings

用户明确要求维护/查看数据提取规则配置时可以打开 `data` Tab；普通提取任务不需要自动跳设置页。

## 提取策略

1. **先复用、后创建。** 先查现有提取器；只有无匹配时才创建。
2. **真实样例驱动。** 新规则的每个字段都必须能回到真实日志样例验证。
3. **最小字段集。** 不因为日志里有很多数字就全部提取，只围绕用户问题设计字段。
4. **区分“规则已生成”和“数据已提取”。** 创建候选规则不等于已经得到数据结果。
5. **利用页面验证。** 候选能力应由当前已加载日志验证命中数/字段解析后再持久化。
6. **避免重复规则。** 新建前再次确认已有能力没有等价字段/模块覆盖。
7. **大日志不进模型。** AI 只看代表样例、字段摘要和验证结果；实际大范围数据处理交给前端/规则执行引擎。
8. **不要自动导航。** 只有用户要求查看数据页/设置页，或完成提取后用户明确需要可视化时才触发 UI 动作。

## 常见任务决策示例

### 用户：提取每个接口的耗时

- 先 `list_data_extraction_rules` 搜耗时/接口字段。
- 有现成规则 → `run_data_extraction`。
- 没有 → 从当前真实日志选择包含“接口名 + 耗时”的代表样例 → `create_data_extraction_capability` → 页面验证并执行。

### 用户：现在有哪些可提取数据

- 只调用 `list_data_extraction_rules`，直接回答能力名称、模块范围和字段。

### 用户：把当前日志里的某项数据做成以后可复用的提取器

- 先确认没有等价规则。
- 基于当前真实样例创建候选能力。
- 让页面验证后保存；不要只生成一段无法执行的正则文本。

## 停止条件

- 已找到合适现有提取器并已经发起/完成所需提取。
- 新候选提取能力已经基于真实样例生成并进入页面验证。
- 当前没有真实日志样例，无法安全创建规则。
- 用户只是查询已有能力目录，已经回答完成。

## 最终回答要求

明确区分：

- 复用了哪个已有提取器。
- 新建了哪个候选提取能力以及字段。
- 页面是否已经验证通过。
- 是否已经实际完成提取，以及真实结果行数（只有 Tool/页面返回后才能写）。
